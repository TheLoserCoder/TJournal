# ADR-0008: Renderer design system with layered tokens

## Status

Accepted

## Context

Renderer уже содержит Radix/Base UI primitives и compact trade workspace, но стили исторически находятся в одном `styles.css`. В нём одновременно присутствуют ранние глобальные правила и FND-008/FND-009 tokens. Это усложняет смену палитры, поддержание Light/Dark и согласованную миграцию таблиц, форм, toolbar, dialogs и статистики.

Figma Dashboard (Community) нужен только как визуальный ориентир: спокойные поверхности, grid alignment, скруглённые контейнеры и аккуратная иерархия. Перенос содержимого dashboard не входит в решение.

## Decision

- CSS custom properties являются авторитетным источником design tokens.
- Токены имеют слои `reference -> semantic -> component`.
- Light и Dark задаются самостоятельными mappings; Dark не строится инверсией Light.
- Общее presentation поведение остаётся в renderer `components/ui/*`; feature Views получают только ViewModels и callbacks.
- Старые правила изолируются в CSS cascade layer `legacy`, новые tokens и presentation rules подключаются отдельными stylesheet layers.
- Цветовая система использует indigo как основной accent, blue/violet как chart accents, muted positive/negative для финансовой семантики и warning для неполных данных.
- Для обычного добавления используется основной indigo treatment, визуально связанный с active navigation. `secondary-accent` и `accent-ghost` являются двумя спокойными вторичными ролями без positive green; positive остаётся финансовым и success-смыслом. Иконки Close и delete всегда red/rose, но Close остаётся нейтральным dismiss-action без красной заливки в idle, а delete сохраняет danger-role и подтверждающие тексты.
- Радиусы ограничены 4/6/10 px, pill оставлен только для статусов; elevation снижена, чтобы поверхности не выглядели тяжёлыми островами.
- Trades имеют вертикальную композицию `PageHeader -> grouped KPI summary -> quick entry -> table`; summary занимает доступную ширину и на широкой рабочей области остаётся одной невысокой строкой из трёх смысловых групп: финансы, результативность и активы. Группы разделяются тонкими линиями; все KPI используют одну карточную геометрию и один размер чисел, а финансовая семантика передаётся цветом текста и границы. Соседние блоки рабочей области разделяются одним компактным tokenized interval.
- Адаптивность Trades определяется шириной рабочей области (`@container` на `.page-content`), а не шириной окна. Пока контейнер шире `72rem`, summary остаётся одной строкой; ниже группа активов переносится целиком, ниже `45rem` группы складываются вертикально. Порог `45rem` — заготовка мобильной версии, проверяется zoom/devtools и не меняет минимальный размер окна.
- Quick-entry держит одну компактную строку за счёт пропорциональных колонок и единой высоты контролов; `DirectionToggle` не выше соседних полей. Ниже `56rem` поля переходят на трёхколоночную сетку, действия — на отдельную строку, а подпись `С деталями` заменяется иконкой.
- Quick-entry и selection toolbar живут в одной grid-области: неактивный слой получает `data-active="false"`, `inert` и `aria-hidden`. Смена режима не меняет высоту рабочей области и не сдвигает таблицу.
- DataTable получает ширину из `table.getTotalSize()`, поэтому сохранённые размеры колонок создают локальную горизонтальную прокрутку; scroll-контейнер фокусируем, имеет локализованную подпись и tokenized scrollbar.
- Select, Combobox, Popover и DatePicker используют общую визуальную основу и одинаковое короткое overlay-появление с поддержкой reduced motion. `DirectionToggle` используется для двух фиксированных trade directions, а reset календаря находится в header-area.
- Overlay consumers используют булево controlled-состояние `open`; table filters не переключают состояние инверсией. Закрытие получает отдельную короткую exit-transition без изменения геометрии trigger.
- `TimeField` является одним прямым редактируемым control с иконкой часов и форматом `HH:mm`; отдельный native/portal picker не используется, потому что его системное меню нельзя привести к общей визуальной системе и оно вызывало нежелательные blur/state-переходы.
- DataTable передаёт selected state на `tr`; фиксированная высота строки и inset outline предотвращают layout shift при выборе.
- Trades при выделении строк показывает selection toolbar и деактивирует quick-entry слой без удаления из DOM; Accounts/Assets используют ту же зарезервированную высоту и не компенсируют её отрицательным margin.
- Account selection является controlled state workspace presenter: текущий выбор по `account.id` имеет приоритет над remembered localStorage fallback, чтобы reconciliation не создавала oscillation.
- Account form визуально отделяет account identity от account + global asset cost profiles. Это не меняет persistence contract в рамках FND-014.
- Dashboard content, новые analytics и функциональные изменения исключены.
- Renderer redesign не требует изменений domain/application/IPC/SQLite.

## Consequences

Смена палитры, темы, радиусов или плотности выполняется через tokens, без поиска по feature JSX. Новые primitives имеют единые accessibility и overlay rules. Legacy CSS можно удалять постепенно, когда все потребители подтверждены тестами.

Компонентные tests и manual Electron smoke становятся частью visual change acceptance. Feature CSS остаётся layout-only. Прямые цвета, локальные радиусы и тени считаются архитектурным нарушением.

## Alternatives considered

- Полная замена CSS одним новым файлом: отклонено из-за риска потерять существующие states и незавершённого рабочего дерева FND-010–013.
- Tailwind-only theme: отклонено, потому что primitives уже используют CSS variables и renderer должен иметь runtime Light/Dark mappings.
- Динамический пользовательский редактор палитры: отложено; сейчас нужна стабильная documented system palette.

## Amendment 2026-09-24 (FND-028)

Владелец заменил indigo-язык на терминальную палитру по референсу `stitch_(2).zip`, сохранив слои токенов, MVP-границу renderer и все правила приёмки выше.

- Акцент — thermal orange: `--ref-brand-500` является заливкой действия, `--ref-brand-600` — читаемым текстовым тоном, `--color-accent-ink` — тёмной подписью на заливке, поэтому заполненная primary-кнопка сохраняет контраст не ниже 4.5:1. Blue становится вторичным/edit/info-акцентом, violet остаётся цветом пополнения, warning — выводом.
- Поверхности тёмной темы используют tiers референса (`#0b0f17` canvas, `#111827` surface, `#161f30` subtle, `#1b2434` overlay) со структурными линиями `#22304a`/`#2f3f5c`. Светлая тема сохраняет холодный neutral canvas, белые поверхности и более тёмные статусные тона; обе темы объявляют собственные mappings и тени.
- Типографика: `--ref-font-sans` и `--ref-font-mono` — единственные семейства. Числовые readout-ы (`.ui-numeric`, значения метрик, result-чипы, таблицы статистики) используют monospace с tabular figures. Бинарные шрифты не добавляются: списки начинаются с Inter/JetBrains Mono и деградируют до платформенных UI/monospace-шрифтов, поэтому offline-сборка остаётся без новых зависимостей.
- Скроллбары: `--scrollbar-*` теперь оформляют страницу, диалоги, select/popover, списки тегов и области статистики, а не только таблицу.
- Chrome диалога: содержимое владеет padding-ом, sticky header и sticky action footer, поэтому длинная форма сохраняет заголовок и действия, а прокручивается только тело.
- Одна роль подтверждения: обычные действия save/create/apply используют `primary`. Варианты `success` и `secondary-accent` удалены: зелёный зарезервирован за финансовым результатом, а добавление строки, повтор и отмена используют один нейтральный `secondary`, поэтому обычный CTA не выглядит как прибыль, а у похожих действий нет двух разных лиц.
- Новые общие presentation-части: `TabList` (`components/ui/tab-list.tsx`) заменяет feature-local кнопки вкладок, `ui-meter` показывает точный процент компактной шкалой, `ResultDistributionRing` рисует существующие win/loss/break-even counts подписанным кольцом.

## Amendment 2026-09-24 (FND-031 — blue palette)

Владелец заменил терминальный акцент FND-028 на согласованную синюю палитру. Слои токенов, MVP-граница renderer, правила приёмки и остальные решения FND-028 (chrome диалога, удалённые варианты кнопок, `TabList`, `ui-meter`, кольцо распределения) сохраняются; заменяется только цветовая часть.

- Акцент действия — blue: `--ref-brand-500` (`#2563eb`) является заливкой, `--ref-brand-600` (`#1d4ed8`) — читаемым текстовым тоном, `--ref-brand-ink` (`#ffffff`) — подписью на заливке. Белая подпись на заливке даёт контраст не ниже 4.5:1 в обеих темах, поэтому тёмная подпись больше не используется.
- Вторичные роли разведены, чтобы синий акцент не смешивался с ними: edit/info — indigo (`--ref-indigo-500`/`--ref-dark-indigo`), пополнение — violet, вывод — warning. Ряд графиков — blue → teal → violet → amber, поэтому соседние серии различимы. Пользовательские tag-цвета сохраняют собственную палитру, включая `tag-orange`.
- Тёмная тема получает `#60a5fa` как читаемый акцентный текст и приглушённую подложку `#16243d`; заливка действия остаётся `#2563eb` с белой подписью. Light и Dark по-прежнему объявляют независимые mappings.
- Винрейт быстрой сводки получает компактное кольцо (`components/charts/win-rate-ring.tsx`) по уже рассчитанному домену `winRate`; горизонтальная шкала в сводке заменена, точное значение остаётся рядом. Кольцо `ResultDistributionRing` на странице статистики сохраняется и отвечает на другой вопрос (доли wins/losses/neutral).
- Карточки быстрой сводки выравниваются: группы получают пропорцию по числу карточек (2 + 5 + 2), поэтому все девять метрик имеют одинаковую ширину и высоту, а не только совпадающий кегль значения.
- Трек калькулятора процентов/риска перестаёт резервироваться постоянно: сетка быстрого ввода добавляет колонку конверсии только при непустом `%`/`R`-превью, поэтому теги следуют сразу за единицей результата, а в режиме пополнения/вывода остаются только три поля (`Счёт`, `Актив`/сумма).
- Выпадающие подсказки используют тематическую поверхность `--color-surface-elevated` с border/shadow popup вместо инверсии палитры, поэтому Light и Dark читаются одинаково.

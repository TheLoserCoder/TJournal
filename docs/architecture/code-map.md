# Карта проекта

Карта проекта — краткий источник навигации, а не полный список файлов. Она обновляется вместе с кодом при создании, перемещении или удалении модулей, публичных контрактов, маршрутов, адаптеров и потоков данных.

## Текущая структура

| Область                  | Назначение                                                                              | Публичная граница                                                                             | Зависимости                           |
| ------------------------ | --------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- | ------------------------------------- |
| `apps/desktop`           | Electron shell, bootstrap, preload, React entry points и конфигурация electron-vite     | `@tjournal/desktop`                                                                           | Модули и platform-адаптеры            |
| `modules/trade`          | Агрегат сделки, qualitative notes/review, Decimal-расчёты, валидация, R и use cases     | `@tjournal/trade`, browser-safe `@tjournal/trade/calculations` и `@tjournal/trade/note-rules` | `modules/instrument`, Decimal.js      |
| `modules/account`        | Счета, жизненный цикл, account-specific 1R, cash movements и read model баланса         | `@tjournal/account`                                                                           | Нет                                   |

## Как начинать исследование

CodeGraph используется для ориентации, а не как источник архитектурной истины. Рабочая последовательность: обновить индекс инкрементально, найти владеющий публичный символ, посмотреть callers/callees и связанные тесты, затем прочитать исходник и тесты; границу подтвердить ADR, этой картой и `pnpm architecture`. После изменения исходников переиндексировать затронутые файлы. Эвристические cycle/hot-path/impact отчёты требуют подтверждения dependency-cruiser, TypeScript или runtime-тестом.

| Изменение                               | С чего начать                                                                            | Следующая граница                                                  | Обязательное подтверждение                                                  |
| --------------------------------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------ | --------------------------------------------------------------------------- |
| Правило сделки или расчёт USD/%/R       | `modules/trade/src/domain`, `modules/trade/src/application`, публичный `@tjournal/trade` | Порт в `modules/trade/src/contracts`, затем adapter                | Domain/use-case tests, Decimal-инварианты, `pnpm architecture`              |
| Счёт, баланс или движение денег         | `modules/account`, затем account commands в desktop application                          | `SqliteAccountStore` и typed IPC                                   | Account tests, transaction/Undo regression                                  |
| Инструмент, категория или профиль тиков | `modules/instrument` и его публичная граница                                             | Instrument commands/registrar, `SqliteInstrumentStore`             | Domain/profile tests, migration tests при schema change                     |
| Vault, backup или recovery              | `modules/journal` contracts/use cases                                                    | `platform/database` backup/storage adapters и vault IPC registrar  | Integrity/checksum tests и изолированный recovery smoke                     |
| Renderer-поведение                      | Feature presenter → View → feature CSS; View не начинает с gateway                       | `apps/desktop/src/renderer/gateway`, typed preload/shared contract | Component test, accessibility/Electron E2E при пользовательском поведении   |
| IPC/API-контракт                        | `apps/desktop/src/shared` и preload surface                                              | Capability registrar → application use case                        | Boundary schema tests, typecheck, no direct adapter import                  |
| Табличный read model или фильтр         | `modules/trade/src/contracts/journal-table-reader.ts`                                    | SQLite reader/SQL/functions → table presenter                      | Reader/config tests, bounded pagination and query-plan checks               |
| Быстрая или полная статистика           | `modules/analytics` contracts/use cases                                                  | SQLite fact source → worker/IPC → statistics presenter             | Exact Decimal analytics tests, bounded data/read verification               |
| Новая cross-module зависимость          | Публичный `index.ts`/package `exports` владельца                                         | `tsconfig` project reference потребителя                           | `pnpm typecheck` и `pnpm architecture`                                      |
| Релиз Windows                           | Task Master release task и ADR-0018                                                      | CI artifact → install/upgrade smoke → GitHub Release               | `pnpm verify:release`, Authenticode status, SHA-256 и download verification |

Renderer design-system boundary: `apps/desktop/src/renderer/styles/design-tokens.css` owns reference, semantic and component tokens; `styles/design-system.css` owns presentation primitives and visual composition; `styles/data-table.css` owns DataTable scroll, sticky header, resize-guide and scrollbar mechanics; `features/journal/trades-page.css` owns Trades workspace composition and its container queries; `features/statistics/statistics-page.css` owns the Statistics composition (KPI tone edges, meters, distribution ring layout and chart/ring reflow). `components/ui/tab-list.tsx` is the single in-page view switch, `components/charts/result-distribution-ring.tsx` renders the existing win/loss/break-even counts as a labelled ring, and `components/charts/win-rate-ring.tsx` renders the domain `winRate` as a compact donut next to its exact value. The action palette is one blue (`--ref-brand-*`); edit/info uses indigo, and chart series use blue → teal → violet → amber. Scrollbars are tokenized through `--scrollbar-*` for the page, dialogs, popups, tag lists and statistics regions, and `.ui-dialog-header`/`.ui-dialog-actions` are sticky chrome of the dialog scroll container. `styles.css` assembles Tailwind, calendar styles, token styles and legacy rules isolated in the `legacy` cascade layer. `.page-content` is the adaptation container (`container-type: inline-size`), so feature layout reacts to the actual workspace width. `components/ui/*` remains presentation-only; feature CSS owns layout only. `features/journal/account-selection.ts` owns the pure selection reconciliation rule, while `use-journal-workspace-presenter.tsx` owns the controlled account selection and vault-scoped preference. `App.tsx` gates the workspace behind `features/vault/vault-onboarding-view.tsx`: no journal UI is mounted until a vault is resolved and open, and `components/ui/dialog.tsx` supports a non-dismissible mode for blocking vault/account onboarding. Domain, application, preload, IPC and database layers do not depend on these files.

## Поток приложения

```text
Renderer feature -> typed preload API -> main IPC registrar -> application use case
  -> port interface -> platform/module adapter -> SQLite or file system
```

Undoable-мутация идёт через application command в `apps/desktop/src/main/application/*`: команда снимает снимок внутренними use case, выполняет инверсию через порт `CommandHistory`, возвращает `{ value, changedResources }`, и только после успеха registrar публикует `data:changed`.

Для зависимых представлений поток продолжается после транзакции: `SQLite triggers -> data_revisions -> CommittedChangeCoordinator -> data:changed -> renderer presenter -> analytics worker -> summary/report ViewModel`. Worker читает только снимок vault и не участвует в записи. Полная Statistics page использует `AnalyticsFactSource -> SqliteAnalyticsFactSource`, потоково читает только нужные поля и возвращает ограниченные time-series/breakdown DTO. Account read model агрегирует opening balance, saved trade USD impacts и отдельные cash movements; analytics считает только trades и показывает accounted balance отдельным полем. Фильтры таблицы передаются в quick analytics типизированными полями (`entryKinds`, `resultUnits`, `netResultBounds`, `textQuery`) и не меняют persistence. Фильтры деталей (`detailBounds`, `reviewStatuses`, `notePresence`) выполняются в том же bounded reader; расчётные тики принадлежат профилю «счёт–актив» (`account_instrument_defaults`), а page row отдаёт ограниченную скалярную проекцию деталей — ADR-0017.

## Реализованные ключевые файлы

- `apps/desktop/src/main/desktop-container.ts` — composition root Awilix в main process: единственное место создания concrete adapters для IPC и application-команд; отдельным composition root является entry point analytics worker (`main/analytics-worker.ts`), который сам создаёт read-only SQLite-адаптеры своего потока. `VaultSessionCoordinator` активирует vault одной операцией (проверка кандидата, сброс ревизий и истории, запоминание пути), а `SqliteTradeUnitOfWork` даёт атомарную границу для записи сделки и 1R счёта.
- `apps/desktop/src/main/register-ipc-handlers.ts` — только композиция: собирает `IpcRegistrationContext` (logger, безопасный результат, capture/publish `data:changed`) и делегирует capability-registrar-ам `register-{vault,tag,trade,account,instrument,history,settings,diagnostics,analytics}-ipc-handlers.ts`. Каждый registrar регистрирует ровно свои каналы, парсит внешний ввод Zod-схемой, публикует изменения только после успешной команды и получает узкий интерфейс зависимостей вместо Awilix cradle (ADR-0014). Каналы `instrument-profiles:*` принадлежат instrument-registrar-у и instrument use cases, поэтому каталог и профили расчёта пишет только `modules/instrument`.
- `apps/desktop/src/main/application/*` — application-команды Undo/Redo (`TagCommands`, `CashMovementCommands`, `AccountCommands`, `InstrumentCommands`, `TradeCommands`, `TradePreferencesCommands`): снимок через внутренние use cases, инверсия через порт `CommandHistory` (`application/command-history.ts`, реализуется `history/undo-redo-history.ts`), результат `CommandOutcome { value, changedResources }`. `CommandHistory` дополнительно оборачивает `execute`/`undo`/`redo` в порт `CommandTransaction` (`application/command-transaction.ts`, реализуется `history/sqlite-command-transaction.ts` на транзакции активного vault), поэтому многошаговая инверсия откатывается целиком, а неудачная команда остаётся повторяемой.
- `dependency-cruiser.cjs` и `eslint.config.mjs` — исполняемые границы: inner layers (domain/application/contracts) и desktop application-команды не видят apps/platform-адаптеры, Electron, React, SQLite, Drizzle, filesystem/process/worker API и concrete history/database adapters; View не импортирует gateway/preload; cross-module импорты идут только через публичные entry points; main/preload/shared runtime-код использует только скомпилированные корневые entry points модулей, а browser-safe подпути (`calculations`, `note-rules`, `palette`, `report-contracts`) остаются renderer-only; IPC registrars не импортируют database-адаптеры; `max-lines` — ошибка выше 500 production-строк с записанными исключениями. `test/architecture-fixtures/verify-guards.mjs` сажает по одному нарушению на правило — dependency-cruiser-правила прогоняются по fixture-дереву, ESLint-правила (`window.tjournal`, `max-lines`) линтуются репозиторным конфигом от fixture-корня — и падает, если правило перестало срабатывать.
- `apps/desktop/src/preload/index.ts` и `apps/desktop/src/shared/*` — единственная поверхность, доступная renderer.
- `apps/desktop/src/renderer/gateway/*` — renderer adapter к preload; `features/*/*presenter*` — MVP presenter; `features/*/*view*` — чистые React Views. `use-journal-presenter.ts` владеет разрешением vault (`vaultResolved`/`vaultError`) и действиями `createVault`/`openVault`/`validateVault`/`revealVaultFolder`; `features/vault/vault-onboarding-view.tsx` — блокирующий View первого запуска, пока vault не создан или не открыт; `features/journal/use-vault-settings-presenter.ts` и `vault-settings-view.tsx` — карточка vault на странице настроек (смена, открытие папки и проверка). `App.tsx` монтирует workspace с ключом `vaultPath:vaultSessionId`, поэтому успешная активация vault начинает новую сессию без черновиков предыдущего (UI-019), а `use-journal-workspace-presenter.tsx` возвращает `QuickEntryOutcome`, сохраняет результат и теги при неуспешной записи и переиспользует уже созданный актив при retry.
- `apps/desktop/src/renderer/components/ui/*` — presentation-only Radix/Base UI/DayPicker wrappers, включая единый компактный календарь в режимах выбора даты и диапазона с header reset, прямой `TimeField`, `DirectionToggle` и `SelectionToolbar`; `components/data-table.tsx` — нейтральная TanStack Table/View с portal filters, визуальным resize-guide, локальной горизонтальной прокруткой от `table.getTotalSize()` и фокусируемым scroll-регионом; `components/data-table-filter.ts` — контракт типов фильтров колонок; `components/ui/number-filter-panel.tsx`, `text-filter-panel.tsx`, `datetime-range-panel.tsx`, `filter-reset-button.tsx` и `multi-select.tsx` (`MultiSelectPanel`/`CheckboxListPanel`) — общие панели редактирования фильтров; кнопка сброса всех фильтров живёт в тулбаре рабочей области рядом с настройками вида. `features/journal/use-journal-workspace-presenter.tsx` и `use-trades-table-presenter.tsx` — UI-state и callbacks без gateway/IPC в View; блок `.table-toolbar-actions` держит сброс фильтров и настройки вида (иконка `Settings`) у правого края тулбара таблицы. Все времена сравниваются в UTC-таймзоне, а диапазоны `greater than`/`less than` строгие, `between` — включительный.
- `features/journal/trades-page-view.tsx` — компактное рабочее место сделок; `trade-details-dialog-view.tsx`, `trade-summary-settings-dialog-view.tsx`, `cash-movement-dialog-view.tsx`, `asset-create-dialog-view.tsx` и `table-layout-dialog-view.tsx` — чистые Views диалогов. Двойной клик по строке таблицы открывает редактор строки (сделка или движение денег), колбэк передаётся в нейтральный `DataTable`. Trade details View принимает presenter-owned entry/review note drafts и явный review status; лимит notes отображается через browser-safe `@tjournal/trade/note-rules`. Результат перевода в USD показывается инлайн в тулбаре (`.quick-entry-conversion`) сразу после поля результата и единицы и появляется только при непустом значении; база процента — tooltip на этом элементе, отдельной подсказки под тулбаром нет. Пустой символ актива не создаёт актив: кнопка «Добавить» выключена, а неизвестный символ открывает `AssetCreateDialogView` с выбором типа. Временные поля подробной формы явно disabled и не меняют модель сделки или SQLite. Каждая data-колонка объявляет фильтр в `trade-table.config.ts` (`TRADE_TABLE_FILTER_SCHEMAS`), предикаты и состояние живут в `trade-table-filters.ts`, панели собираются в `trade-table-filter-panels.tsx`; `trade-table-columns.tsx` выводит authoritative `netResultUsd`, исходную единицу и тип актива (категорию из карты инструментов) отдельными колонками. Порядок колонок канонический (Результат → Актив → Теги → Тип → Счёт → Дата) и задаётся конфигом; скрытые по умолчанию detail-колонки (цена входа, стоп-лосс, лоты, комиссия, спред, число выходов, review status, заметки) включаются из настроек вида и фильтруются типизированно; колонка «Теги» показывает цветные метки, сворачивает непоместившиеся в `+N` с popover и имеет multi-select фильтр с опцией «Без тегов». Инлайн-поля 1R в тулбаре нет: значение задаётся в `table-layout-dialog-view.tsx` и применяется из `use-journal-workspace-presenter.tsx`; при применении настроек вида 1R сохраняется на счёте (`account-risk-update.ts` собирает `updateAccount` с `defaultRiskUsd` и сохранением настроек активов), поэтому не сбрасывается при перезапуске или смене счёта; пустое значение при отправке R-сделки открывает диалог ввода с подсказкой (`journal-view.tsx`).
- `features/journal/accounts-table-view.tsx` и `assets-table-view.tsx` — таблицы Accounts/Assets; `entity-table.config.ts` владеет layout, exhaustive filter-схемами и общей видимостью, `entity-table-filters.ts` — предикатами, `entity-filter-panel.tsx` — единой фабрикой панелей. Двойной клик по строке открывает редактор счёта/актива. Любая новая колонка обязана объявить тип фильтра: несоответствие ловится typecheck и тестами `*.config.test.ts`. Удаление и восстановление выбранных записей идут через `CatalogPresenter.requestBulkAction`: подтверждение, последовательные одиночные команды (связанные записи архивируются, свободные удаляются) и сохранение остатка для retry; `ConfirmDialog` получает `busy` и блокирует действия, пока команда выполняется (UI-018), а локализованные подписи категорий берутся из `INSTRUMENT_CATEGORY_LABEL_KEYS`.
- `features/journal/account-asset-editor-dialogs.tsx` — единственное место диалогов счёта и актива: `AccountAssetEditorDialogs` рендерится на уровне `journal-view.tsx`, поэтому редакторы не зависят от активной страницы; поле актива — Combobox с вводом и порядком последних использованных активов. `catalog-page-view.tsx` отвечает только за вкладки (счета, активы, теги), quick-create и композицию таблиц; `tags-table-view.tsx` и `tag-editor-dialog-view.tsx` — каталог тегов и полный редактор, `tag-chip.tsx`, `tag-overflow-list.tsx` и `tag-picker.tsx` — цветная метка, overflow `+N` и multi-select выбора тегов в сделке.
- `modules/journal/src/contracts/journal-storage.ts` — контракт жизненного цикла vault и read-only проверка pending-миграций; каталог инструментов принадлежит `modules/instrument`. `contracts/vault-backup-store.ts` и use cases `Create/List/Verify/RestoreVaultBackupUseCase` владеют правилами резервирования, проверки и восстановления без файловой системы в inner layer. `OpenVaultUseCase` делает проверенный снимок до миграции; `contracts/vault-folder-opener.ts` — порт открытия папки vault.
- `platform/database/src/sqlite-journal-storage.ts` — структура vault, SQLite, идемпотентная миграция, `integrity_check` и не изменяющая активную сессию проверка `inspectVault` (маркер, наличие базы и `PRAGMA integrity_check` на отдельном read-only соединении); миграция кандидата при `openVault`/`createVault` также идёт на отдельном соединении, поэтому ошибка не закрывает активный vault.
- `platform/database/src/sqlite-vault-backup-store.ts`, `vault-backup-manifest.ts`, `vault-layout.ts` — `node:sqlite.backup()` со снимком WAL, Zod-манифестом, SHA-256, `integrity_check`, staging/rename, retention только автоматических снимков и восстановлением в новый vault с новым ID. `apps/desktop/src/main/register-vault-backup-ipc-handlers.ts` регистрирует typed backup/list/verify/restore; presenter/View Vault settings обращаются только через gateway/preload. Backup не публикует `data:changed`; выбор destination остаётся в Electron picker. ADR-0015 и `docs/engineering/backup-recovery.md` фиксируют формат и процедуру.
- `tools/recover-vault.mjs` — офлайн-вызов того же проверяющего адаптера по ID копии для случая, когда повреждённый исходный vault нельзя открыть в приложении; создаёт новый vault без обращения к повреждённой базе.
- `platform/database/src/sqlite-vault-database.ts` — общая SQLite-сессия, read-only worker-сессия, транзакционные миграции, data revisions и вложенные транзакции через savepoints для атомарных use-case операций; там же остаётся инфраструктурный seed стартового каталога инструментов при создании vault (seed не делает `modules/journal` владельцем инструментов). Migration `009-trade-notes-and-review` добавляет nullable trade notes и constrained review status с legacy default `unreviewed`; migration `010-account-instrument-ticks` добавляет nullable `tick_size`/`tick_value_usd_per_lot` в `account_instrument_defaults` и backfill-ит их из `instrument_calculation_profiles`. `sqlite-trade-store.ts` — сделки, выходы, bounded detail-проекция page row и vault-настройки риска. `sqlite-journal-table-sql.ts` владеет SQL-фрагментами bounded reader (arms, bounds, tags, detail-фильтры), `sqlite-journal-table-cursor.ts` — кодеком keyset-курсора. `sqlite-trade-summary-fact-source.ts` — потоковый источник быстрой сводки (узкая проекция одним `iterate()` без exits/tags/notes), а `trade-row-mapping.ts` — общие правила маппинга строки сделки для полного чтения и сводки. Историческая перепривязка 1R снимает и восстанавливает только колонки risk binding затронутых сделок, а не полный снимок журнала (ADR-0004).
- `platform/database/src/sqlite-account-store.ts` и `sqlite-instrument-store.ts` — dedicated adapters для CRUD/lifecycle/defaults, account-specific risk и Decimal-based account balance projection; `sqlite-instrument-store.ts` — единственный writer каталога и `instrument_calculation_profiles` (create/update/replace и точечный `saveInstrumentProfile`). Migrations `006-accounts-assets` и `007-cash-movements` добавляют account attribution, risk defaults, movement records и revision triggers.

Черновик полей и профилей счёта живёт в `use-catalog-presenter.ts` (`accountDraft`, `accountDefaultsStatus` с локальным Retry): сохранение существующего счёта заблокировано, пока профили не прочитаны, а `null`-ответ чтения не подменяется пустым списком (UI-017). Tables используют общие схемы фильтров, открывают редактор по двойному клику и не содержат gateway-логики.
- `apps/desktop/src/renderer/features/journal/journal-view.tsx` — shell и навигация (сделки, счета и активы, статистика, настройки; страницы «Главная» нет, старт — сделки) и страница настроек: карточки «Интерфейс» (тема, язык) и «Vault» (`VaultSettingsView`: путь, смена через нативный диалог, открытие папки и полная проверка перед применением). `use-trade-settings-presenter.ts` теперь отвечает только за нейтральные границы/затраты в диалоге сводки и сохраняет существующий vault `riskBinding`; риск (1R) и профили расчёта инструментов редактируются у сущностей — в счёте и в активе.

- `modules/trade/src/domain/*` — canonical result, one-source USD/%/R conversion, точная валидация, qualitative entry/review notes, explicit review status, формула исполнения, классификация результата и остатки выходов; browser-safe `@tjournal/trade/calculations` публикует общие вычисления, а `@tjournal/trade/note-rules` — лимит и нормализацию заметок для renderer. Сделка хранит `tagIds` и qualitative review; `TradeTagReferenceReader` (порт, принадлежащий trade) проверяет существование тегов, а `SqliteTradeStore` пишет `trade_tags` в одной транзакции с самой сделкой и загружает связи batch-запросом. `TradeUnitOfWork` (порт trade, реализация `SqliteTradeUnitOfWork`) делает запись сделки и запомненного 1R счёта одной атомарной операцией; правка финансового ввода определяется `resolveResultInput` сравнением с сохранённой сделкой. `modules/analytics/src/calculate-trade-summary.ts` строит независимую от таблицы торговую статистику на том же authoritative net USD результате; `summarizeTradeFacts` принимает поток `TradeSummaryFact` (порт `TradeSummaryFactSource`) и делает один проход с постоянной памятью, а `calculateTradeSummary` остаётся обёрткой над полным списком.

Renderer-инвалидация: `features/journal/refresh-resources.ts` (матрица ресурс→группа) и `refresh-scheduler.ts` (коалесцинг, single-flight, fallback после мутации); baseline и решения — `docs/engineering/query-performance.md`.
- `modules/trade/src/contracts/journal-table-reader.ts` и `platform/database/src/sqlite-journal-table-reader.ts` — bounded read model таблицы сделок (ADR-0013): двунаправленный keyset-курсор, фильтры и allowlist-сортировки в SQLite, точные Decimal-границы через `tjournal_decimal_cmp`, Unicode-aware lowercase text query по row ID и заметкам, cap страницы 200; `sqlite-journal-table-functions.ts` регистрирует Decimal-сравнение и lowercase matching на каждом vault connection. Лёгкие table DTO не содержат executions/exits/note contents. Renderer хранит не более трёх страниц (`features/journal/journal-page-window.ts`), а `components/data-table.tsx` виртуализирует абсолютное окно без скачка scroll-позиции; полная сделка для редактора читается точечно через `trades:get`, старый `trades.list` удалён из IPC/preload/gateway; счётчики тегов — `tags:counts`.

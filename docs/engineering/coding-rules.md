# Правила разработки

Корневой [AGENTS.md](../../AGENTS.md) является обязательной исполнимой конституцией проекта. Этот документ поясняет её и не должен ей противоречить.

Распределение ролей моделей и требования к передаче планов исполнителям зафиксированы в разделе `Model roles and handoff` корневого `AGENTS.md`; здесь они намеренно не дублируются.

- Код проходит typecheck, lint, architecture checks и релевантные тесты.
- Внутренние зависимости не пересекают архитектурные границы.
- Конкретные реализации создаются только composition root.
- Публичные use cases и adapters имеют контракты и тесты.
- Значимые архитектурные исключения фиксируются ADR.
- Renderer следует MVP: View — только отображение и пользовательские callbacks; Presenter — UI-state и преобразование DTO в ViewModel; Renderer Gateway — единственная обёртка над typed preload API.
- Бизнес-правила, валидация и persistence остаются в application/domain и main process. Redesign UI не должен требовать изменения use cases, SQLite или IPC-контрактов.
- Переиспользуемая таблица получает строки, описание колонок, UI-state и callbacks через ViewModel. Она не знает, что отображает сделки, счета или активы, и не вызывает renderer gateway самостоятельно.
- UI primitives содержат только визуальное поведение, доступность и позиционирование. Всплывающие элементы рендерятся через portal, если родитель может прокручиваться или обрезать содержимое.
- Визуальный язык строится на именованных design tokens: общие радиусы, тени, размеры контролов и семантические цвета не дублируются по компонентам. Один набор Lucide-иконок используется для вторичных действий; у каждой icon-only кнопки есть локализованные `aria-label` и tooltip.
- Динамические toolbar-действия резервируют место заранее. Появление выбора, ошибок или массовых операций не должно сдвигать соседние контролы; допустимы только короткие анимации opacity/transform с поддержкой `prefers-reduced-motion`.
- Семантический цвет несёт смысл, а не украшение: обычное добавление — основной indigo treatment, вторичные действия — secondary accent или accent ghost, удаление и close — одна muted rose семья с разными ролями, положительный и отрицательный финансовый результат имеют разные ненавязчивые тона. Денежный знак определяется точным numeric value object, а не JavaScript `number`.
- Renderer design tokens находятся в `apps/desktop/src/renderer/styles/design-tokens.css` и применяются слоями `reference -> semantic -> component`; feature CSS не содержит собственных цветов, радиусов, теней или размеров контролов. Light и Dark имеют отдельные mappings. Полный каталог компонентов и правила расширения зафиксированы в [design-system.md](../architecture/design-system.md) и ADR-0008.
- Для controlled dropdown selection один presenter владеет состоянием: remembered preference не может перезаписывать явный выбор пользователя на последующих рендерах. Reconciliation работает по stable entity id, а не по позиции массива.

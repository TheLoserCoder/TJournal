# Журнал дефектов

Каждый подтверждённый дефект должен содержать ID, серьёзность, окружение, воспроизведение, expected/actual behaviour, статус и ссылку на regression test.

## UI-001 — Нестабильные overlays рабочего места сделок

- Серьёзность: Medium
- Окружение: Electron desktop, light/dark themes
- Воспроизведение: открыть детали сделки, список активов, календарь или настройки колонок; изменить ширину столбца.
- Actual: диалог скачком центрировался после появления; список активов занимал высоту окна и попадал под таблицу; portal-селект мог оказаться под overlay; календарь не наследовал визуальные токены; resize-guide не следовал за курсором.
- Expected: overlays сразу появляются в окончательной позиции и над содержимым, имеют ограниченный viewport и обе темы; resize-guide следует за курсором.
- Status: Fixed in FND-009 follow-up.
- Regression: renderer smoke-test проверяет управление выделением; typecheck, production build и ручной overlay smoke-test обязательны для этого потока.

## UI-002 — Сохранение сделки без изменений отклоняется

- Серьёзность: Medium
- Окружение: Electron desktop, редактирование сделки, включая legacy-сделки без направления.
- Воспроизведение: открыть существующую сделку, не менять поля и нажать «Сохранить».
- Actual: форма отправляет исходные данные повторно; для старой сделки с отсутствующим направлением серверная валидация возвращает ошибку.
- Expected: неизменённая форма закрывается без записи и без ошибки валидации.
- Status: Fixed in the trade editor presenter.
- Regression: `use-trade-editor-presenter.test.ts` проверяет, что неизменённая legacy-сделка не отправляется в `updateTrade`.

## UI-003 — Календарь деталей сделки оказывается под диалогом

- Серьёзность: Medium
- Окружение: Electron desktop, тёмная тема, окно деталей сделки.
- Воспроизведение: открыть детали сделки и нажать поле даты.
- Actual: portal календаря использует базовый слой и отображается под активным диалогом.
- Expected: вложенный календарь и выпадающие списки находятся выше текущего диалога; базовые фильтры таблицы остаются ниже него.
- Status: Fixed with explicit base/dialog overlay layers.
- Regression: renderer typecheck and production build покрывают типизированную передачу слоя; ручной overlay smoke-test обязателен для вложенных popover.

## UI-004 — Закрытие filter popover инвертирует состояние и вызывает мерцание

- Серьёзность: Medium
- Окружение: Electron desktop, table header filters, DatePicker/Popover overlays.
- Воспроизведение: открыть фильтр столбца, закрыть его Escape, click outside или повторным нажатием trigger; быстро повторить для календаря.
- Actual: `DataTable` игнорировал булево `open` от Radix и вызывал toggle-функцию. При повторном callback состояние могло инвертироваться обратно; popup кратко появлялся снова. Focus-правила `:focus` дополнительно давали вспышку на trigger после закрытия.
- Expected: `open=true` открывает только указанный popup, `open=false` закрывает его; закрытие не меняет выбранное значение, размеры toolbar или высоту таблицы.
- Status: Fixed in FND-014 renderer pass. Filter state теперь задаётся явно через `setActiveFilter`, overlay primitives используют общую exit policy, а control focus оформлен через `:focus-visible`.
- Regression: `apps/desktop/src/renderer/App.test.tsx` проверяет open → close → open для date filter; полный Vitest suite, typecheck и production build проходят. Ручная проверка в видимом Electron окне остаётся обязательной.

## ANA-001 — Отрицательная сделка не обновляет худший актив

- Серьёзность: High
- Окружение: Electron desktop, таблица сделок и карточка быстрой статистики.
- Воспроизведение: открыть журнал, выбрать актив с положительным результатом, затем изменить сделку на отрицательное значение.
- Actual: карточка `worstInstrument` могла остаться пустой или содержать прежнее значение до следующего ручного обновления.
- Expected: после успешной записи, Undo/Redo или удаления статистика пересчитывается и показывает актив с наименьшим отрицательным агрегатом.
- Status: Fixed. Invalidation event запускает новый worker-запрос; presenter отбрасывает устаревший ответ, а analytics считает worst по текущему отфильтрованному набору.
- Regression: `modules/analytics/src/calculate-trade-summary.test.ts` проверяет переход сделки к отрицательному значению; SQLite revision test покрывает автоматическую инвалидацию.

## DB-001 — Триггер снимка счёта блокирует создание сделки

- Серьёзность: High
- Окружение: Electron desktop, vault после ранней миграции FND-012.
- Воспроизведение: выбрать счёт или оставить сделку без счёта и сохранить новую сделку.
- Actual: SQL-триггер ссылался на поля строки без префикса `NEW.`. SQLite отвечала `no such column: account_id`; IPC преобразовывал инфраструктурную ошибку в безопасное «Что-то пошло не так».
- Expected: триггер валидирует именно вставляемую или обновляемую строку, а любая ошибка операции сохраняет в локальный лог безопасный код, диагностическое описание и пути полей валидации.
- Status: Fixed. Миграция теперь пересоздаёт оба триггера с `NEW.` при каждом открытии vault, поэтому уже существующие vault исправляются без потери данных.
- Regression: `platform/database/src/sqlite-journal-storage.test.ts` проверяет создание сделки со счётом, USD-снимок и обновление производного баланса.
